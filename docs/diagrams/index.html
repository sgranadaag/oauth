OAuth 2.0 — RFC 6749

The three grants this authorization server implements, each drawn on its own. Plain OAuth 2.0: no PKCE, no OpenID Connect, and accounts scoped to one client.

authorization_code

Authorization Code Grant

A browser app sends the person to the provider, and gets back a single-use code it trades for tokens. state is the whole of its front-channel protection.

client_credentials

Client Credentials Grant

A backend acts as itself, with no person involved. One call with its secret, one access token, and deliberately no refresh token.

ACME Backend · auth-server · Resource API

refresh_token

Refresh Token Rotation

Every renewal spends the token it was given and returns a new one. Presenting a spent token is treated as theft and ends the whole session.
